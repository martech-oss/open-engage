# SOLID・ロジック整合性・パフォーマンス改善

ユーザー承認済みの5項目を実装する。公開APIとDBの変更を許容し、メール指標はメールレポートと統一する。本番へのデプロイや既存スコアの遡及変更は含めない。

## Task 1: Queue送信とCron

- Queue送信は100件・256KB以内に分割する。成功した単位のleaseを保持し、失敗・未送信分だけpendingに戻す。
- Cronをドメイン別タスクに分割し、独立したタスクは他の失敗後も実行する。終了後に失敗を報告する。
- 時刻・Queue・永続化を必要なポートで注入する。
- 100/101/1000件、途中送信失敗、再配信、別タスクの失敗を検証する。

## Task 2: スコア評価と一覧

- 実行時のルール・グレード条件の200件制限を廃止し、全有効設定を評価する。
- 加点を50ルール単位で原子的に書き込み、既存のイベント×ルールの冪等性を維持する。
- 管理画面のルールとグレード条件一覧をcursor/limit方式にする。既定50、最大100、出力はitems/total/nextCursor。
- Client・SDK・MCPの契約と関連テストを更新する。

## Task 3: ダッシュボード

- 専用の集計Repositoryを使用し、不要なレポート内訳を読まない。
- 全Automationの件数集計とDB上位6件取得を行い、一覧の200件上限に依存しない。
- 配信はメールのみ。メールレポートと送信対象・到達判定を共有する。
- ワークスペースのタイムゾーン、推移14日、合計30日を維持する。

## Task 4: 複製

- 一覧・進捗に軽量DTOを用意し集計クエリ1回で取得する。previewをSQLで除外し履歴をページ取得する。
- 詳細取得でもsourceRow/targetRowなど表示不要な列を読まない。
- 読み取り、ジョブ状態、確定書き込みを分割する。種別ごとの変換・書き込み・依存順序を型で網羅する。
- 原子的な最終確定と参照・lease検証は維持する。
- oRPC/Client/SDK/MCPを更新し、query数・previewによる履歴欠落を検証する。

## Task 5: 参加者CSVジョブ

- 既存の同期importProgramMembers/memberImportを再開可能な非同期ジョブに変更する。
- 受付時にCSVと要求キーを永続化しjob IDを返す。同じ要求キー・同じCSVは同じjob、異なるCSVは409。
- 専用Queue PROGRAM_MEMBER_IMPORT_QUEUEを使用しconsumer max_batch_size=1。1回25行を行順に処理する。
- ジョブ状態・行別結果・leaseをDBへ保存し、成功済み行を再適用せず再開する。停止・Queue送信障害をCronで回復する。
- 公開定義を処理単位で再利用する。Contact/Project認可・revision競合・公開定義の固定・行単位の原子的な更新を維持する。
- Clientには受付結果・進捗・行別エラーを表示する。oRPC/SDK/MCPを同時に更新する。
- 入力上限1000行を維持。1000行、途中停止、同一キー再送、入力変更、同じContact複数行、古いleaseを検証する。
- ジョブ用DB追加migrationを用意し、setup CLIのQueue作成とWorker設定も更新する。本番のmigration適用やQueue作成は行わない。

## 検証

関連回帰テスト、型、lint、format、architecture、未使用コード、buildを確認する。同一fixtureでquery数・読み取り量・処理時間の前後比較を記録する。
