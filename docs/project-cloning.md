# 施策一式の複製

`/projects/:id` の「複製」から、関連リソースを含む施策の下書きを作成します。コピー前に名前、担当者・承認者、レビュー日、Project変数を設定し、コピー対象と共有参照を確認します。ブリーフのある施策では担当者・承認者・レビュー日が必要です。

## 操作

1. 「コピー対象を確認」で、その時点のコピー元の版と参照対応表を固定します。公開版があるリソースは公開版を使い、未公開のリソースは最新下書きを使います。
2. 内容を確認して「この内容で複製」を実行します。進捗には準備済みリソース数を表示します。
3. 完了後に複製先を開き、変数・ブリーフ・参加者ステータスを確認します。ブリーフがある場合は通常どおり承認を受けます。
4. 参加者ステータス、フォーム、共通処理、呼び出し元Automation、LPの順に参照先を公開します。Automationを有効化し、実験は別途開始します。
5. 失敗した場合は原因を解消し、履歴の「再試行」を使用します。同じジョブ・同じ複製先から再開します。

コピー元をプレビュー後に編集しても、ジョブの内容は変わりません。別の内容で複製する場合は新しいプレビューを作成します。公開版のフォームが参照する古い参加ステータスと、コピー対象の現行定義が両立しない場合は、コピー元の定義・フォームを揃えて再公開してください。

## コピー範囲

Project設定、ブリーフ、参加者ステータス、Project変数、リンクされたLP・フォーム・Automation・セグメント・計測リンク・既存Transactionalテンプレートをコピーします。LPのフォーム、実験の各案、施策内にリンクされた共通処理も含めます。同じ実リソースは一度だけコピーします。LPが公開時に作成した専用フォームと元の共有フォームは、別の実リソースとして扱います。

画像Asset、タグ、営業担当、Webhook設定、施策外の共通リソースは同じWorkspaceの参照を共有します。内部ID、slug、変数の参照Project、フォーム参加先、計測先をコピー先へ置き換えます。URLは管理対象の公開URLに一致するリンク先のみ置き換え、外部URLや単なる表示文を変更しません。

参加者、静的リストの所属者、成果・接点・費用、実行・承認履歴はコピーしません。動的セグメントはコピーした定義で再評価します。LP・フォーム・Transactionalテンプレート・計測リンクは下書き、Automationは未稼働、実験は未開始になります。公開版と実行スナップショットも引き継ぎません。

## ジョブと復旧

`project_clone_jobs` に要求・固定されたオプション・状態・リースを保持し、`project_clone_mappings` にコピー元スナップショット、コピー先ID、準備結果を保持します。

状態は `preview → queued → running → completed` です。処理中に失敗すると `failed` になり、再試行で `queued` に戻ります。Queueは一回最大20件の準備を進め、続きがあれば再投入します。Cronが未処理ジョブと期限切れリースを回収します。

準備段階は通常のリソーステーブルへ書き込みません。最後に、Workspace内の共有参照とジョブのリースを検証し、D1の一つのatomic batchで全リソース・リンク・完了状態を作成します。途中失敗では全体がロールバックされ、利用途中のコピー先は表示されません。[D1 batchのトランザクション仕様](https://developers.cloudflare.com/d1/worker-api/d1-database/)

`requestKey` はWorkspace内で一意です。開始要求の再送では同じキーを使用し、別の複製を作るときだけ新しいキーを発行してください。Queueの重複配送・リース引継ぎ・完了後の再配送でも複製先を増やしません。

## 公開APIと上限

coreの型・検証とoRPC contractが正本です。RESTは `/projects/{id}/clone-preview`、`/projects/{id}/clones`、`/projects/{id}/clones/{jobId}`、`/projects/{id}/clones/{jobId}/retry` を提供します。SDKでは `client.projects.clonePreview/cloneStart/cloneGet/cloneList/cloneRetry`、MCPでは対応する `preview_project_clone/start_project_clone/get_project_clone/list_project_clones/retry_project_clone` を利用できます。

開発版では、1ジョブを設定・リソース行150件、共有参照200件、コピー元1行800KB、合計8MBまでに制限します。フォーム版・LP版・変数も行数に含まれます。超過はプレビューでエラーにし、部分コピーしません。参照検証は20件ずつに分割し、D1の1文100 bind parameter制約を超えないようにしています。これらはアプリの保守的な上限であり、D1の上限値そのものではありません。[D1 limits](https://developers.cloudflare.com/d1/platform/limits/)

運用上の失敗は設定画面の運用状況とログの `project_clone` 関連イベントから確認できます。定期実行・共通処理の失敗も同じ画面から実行履歴へ移動できます。
