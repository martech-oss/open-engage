# 施策管理・Automation実行制御・再利用

Projectを施策管理の中心として、参加者の進捗と成果、バッチ・共通処理、公開時に固定する共通変数、施策一式の複製を追加しました。Marketingメールと派生機能、SaaS認証追加、外部CRM、ABM、Custom Objects、高度BIは対象に含めていません。

## 通しの操作

1. `/projects` で施策を作成し、参加ステータスのテンプレートを調整します。ブリーフを持つ施策では既存の承認手順を使います。
2. Workspace変数とProjectの上書きを設定します。LP・フォーム・Automationは変数解決に使うProjectを明示します。
3. 施策詳細の複製プレビューで対象と共有参照を確認し、下書きのコピーを作成します。コピー先の変数・担当・承認者・レビュー日を調整します。
4. ブリーフの承認、参加ステータスの公開、フォームの関連付け・公開、共通処理と親フローの公開を行います。LPを公開し、必要なAutomationを有効化します。
5. フォーム送信で新規Contactと施策参加者を登録します。参加者タブで進捗を変更し、訂正が必要なら理由を記録します。
6. バッチの対象人数・サンプルを確認して開始するか、設定済みの定期実行を待ちます。対象の登録進捗と個々のフロー完了を実行履歴で確認します。
7. 共通の営業引き継ぎ結果と、施策の参加日コホート成果を確認します。成果人数・成果率は既存ROI・売上配分とは別の指標です。

## インターフェースと運用

公開の型と検証は `@openengage/core`、API定義は `@openengage/orpc` にあります。REST、SDK、Remote MCPは同じドメイン処理と権限検証を利用します。MCPには参加者・変数・複製・実行履歴などの36ツールを追加し、既存6ツールを維持しています。

設定画面の運用状況は管理者向けです。定期実行の5分以上の遅延、バッチ対象者の登録失敗、共通処理失敗、複製失敗を表示し、対応する実行・施策へ移動できます。各失敗一覧は直近50件、予定の遅延確認は最大200件です。大量運用ではWorkerログも併用してください。

関連ログは `automation.schedule_delayed`、`automation.batch_enrollment_failed`、`automation.callable_await_failed`、`automation.callable_async_failed`、`project.clone_failed` です。通常のQueue再配送、リース回収、Cron回復処理を利用します。デッドレターは既存の管理画面で確認・再投入できます。

## DB変更

- `0023_marketo_programs_automation_variables_clone.sql`: 参加者・定義履歴・フォーム関連付け、Automation実行台帳・親子コンテキスト、変数・公開スナップショット、複製ジョブ、獲得元、計測リンクの下書き状態。
- `0024_variable_revision_tombstones.sql`: 変数の削除・再作成をまたぐ楽観ロックのための削除マーカー。

開発版として型・スキーマを整理しています。旧開発DBのデータ変換・リセットは実施していません。検証はmigrationを最初から適用した空のWorkersテストDBと、既存状態とは別の一時ローカルD1を使用します。既存環境への適用は通常の環境更新手順で行ってください。

バンドル後の公開フォームは、minifyあり・なしの両方をHappy DOMで実行し、条件付き表示と実際の送信ハンドラーを検証します。これは関数の文字列化に混入するバンドラー補助関数によって送信が停止する回帰を防ぎます。

スキーマとDrizzle snapshotを照合し、0024以後の未生成差分がないことを確認しました。

最終の `pnpm check` は27タスクすべて成功しました。Serverは116ファイル578テスト、Clientは82ファイル325テスト、バンドル後の公開フォームは2テストが成功しています。型検査、ビルド、lint、format、未使用コード検査、SQL境界検査、アーキテクチャ検査も通過しました。アーキテクチャ検査は172テストと1,137ソースファイルを確認し、禁止された依存や循環はありませんでした。

検証環境のpnpm shimによる別バージョンの自動取得を止め、子タスクにも設定を引き継ぐため、実行コマンドは以下を使用しました。リポジトリのpackageManager指定・lockfileは変更していません。

```bash
npm_config_manage_package_manager_versions=false pnpm check --env-mode=loose
```

独立した最終レビューでも、実migrationを使う58件のWorkersテスト、8件のDOMテスト、SDK実行経路と型検査を確認しました。SDKのOpenAPI経路から公開フォームHTTP、実際のQueue consumer・Cronへ接続した通しシナリオも成功し、未解決の指摘はありません。
